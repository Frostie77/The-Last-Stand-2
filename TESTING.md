# Verification and remaining device checks

The original, unmodified Not Doppler SWF is v1.31, 8,824,265 bytes, SHA-256 `db326f3ce2f331d3320cd442c88f17152198a5da4cca3d0fb9c1509afb430ea6`. It is excluded from Git and APKs. A desktop Ruffle 0.7.1 smoke test at the Android asset origin reached the preloader, menu, Day 1 journal and Night 1 with all external network requests blocked. The optional CPMStar advertisement was the only external request observed. This is not a complete playthrough or an Android device result.

The HTML bridge merges held movement/fire from touch, stick, hat, buttons and analogue triggers. Pressing A and R2 together must not release fire until both are released. Aim and fire target the same internal Ruffle canvas and use the same untransformed local coordinates, including when the display is stretched. The controller cursor stays where it is when the right stick returns to neutral.

The title, journal and daytime menus draw a crosshair at the same clamped position used for pointer clicks. Night fights use the game's reticle. The overlay follows resize and display-mode changes and hides when FrostFrontend or the background pauses the game.

The touch view owns fingers by stable pointer ID, allowing the movement pad, aiming and Reload/Switch simultaneously. Automated Android tests cover relative aim without snapping, lifting/re-touching, Direct preference, sensitivity, menu transitions, edge clamping, stationary input suppression, pointer reordering, cancellation and saved layouts. FrostFrontend supplies the shared editor and persistence.

For the exact tested Not Doppler v1.31 file, a host-only patch adds phase notifications to the game's showCrosshairs/hideCrosshairs functions in memory. The imported file stays unchanged. Unknown SWF copies are served unchanged and retain Direct aiming. The HTML ignores unrelated FSCommands and duplicate phases. Render Resolution limits Ruffle's physical canvas pixels independently of display density, then scales the finished image; it does not change simulation speed or zombie counts. Performance under heavy fire and chainsaw use still requires an Odin retest.

Activity-level gamepad regression tests cover native focus restoration, first analogue-trigger press, remapped buttons, Auto touch hiding, and movement/aim after closing settings. Scene changes cancel the touch view's own inputs without clearing held controller sources; the HTML tests verify that stick movement and trigger fire remain held until their physical releases.

The HTML bridge also recovers Ruffle's internal keyboard focus when an input event is ignored despite unchanged DOM focus. It re-enters the stage after pointer leave/cancel and encounter changes, and selects the currently visible canvas instead of retaining a hidden connected canvas. These cases are covered by the bridge tests. A separate runtime check with pinned Ruffle 0.7.1 and an independently generated Flash input fixture verifies `Key.isDown`, frame-driven movement and `onPress` firing after focus/leave transitions; this is an engine regression check, not an Odin gameplay result.

Run that optional engine check with `node tests/test_ruffle_recovery.cjs` after preparing the pinned runtime and installing Playwright with Chromium. `TLS2_RUFFLE_PATH` and `TLS2_CHROMIUM_PATH` can select existing local test resources. The fixture is generated in a temporary directory and contains no original game content. `TLS2_BASELINE_HTML` can point to an older wrapper to verify that the original input loss is reproduced.

The Odin tester reports improved controls with the focus recovery, but heavy stutter remains. The next performance changes default antialiasing to Off (Ruffle quality `low`) instead of the previous 4× (`high`), keeping the same render resolution. The optional runtime test also accepts `TLS2_QUALITY=high` to check both configurations and records WebGL multisample allocations. This verifies rendering configuration and input behavior, not an Odin frame-rate improvement.

Native aiming now permits only one movement evaluation in flight, retaining the latest pending position while WebView is busy. Button edges flush that latest position before delivery; presses/releases are never coalesced. Touch down/up/cancel remain ordered, and pause clears pending movement. Activity tests simulate a blocked renderer with 90 aim updates and verify the bounded delivery, latest position, button ordering and pause cleanup. The existing cursor ticker and motion calculation are unchanged.

## Odin checks before release

The particle change gave the Odin tester a small improvement; crowds, running zombies and gunfire still stutter. The next pass reduces lookups in `collisionTest`, `sortZombieDepths` and `sortDeadCats`. It retains each routine's original instructions except selected data reads, adds per-call references to the live mutable lists, and relocates branches after changing instruction sizes. Shared loop counters still read their current root values; splices, deletions and sorting remain visible during the call. The rewriter refuses local/nested/with scopes, target changes, invalid branch boundaries and register/branch overflow. The same exact-file hash guard applies. Independent pinned-Ruffle tests compare empty/crowded lists, nested loops, live mutations, changing counters and branches entering a shared `GetVariable`. Local alternating-order list-loop batches improved by approximately 10–15%; this is not a measured Odin frame-rate gain.

The proximity check now reuses the current zombie and its target coordinates during each iteration. It retains the original muzzle transform, enumeration order, rounded distance and debug text updates. A private pinned-Ruffle comparison exercises the original and updated routines with 25 clip references and seven muzzle positions. The Odin retest will measure the effect during crowded fights.

The sawn-off manual-reload lockout is not reproduced on desktop: the original game reloads from frame 898 through 959, returns to idle frame 873, clears its reload flags and fires again. No reload fix is claimed. `test-reload.ps1` builds/installs the test APK, prompts for an active night fight, equips the sawn-off with one shell through the game’s weapon-swap function, then records a 12-second X/reload test. The setup callback is present only in the Debug APK and leaves weapon discoveries and loadout slots alone. The recorder now samples read-only Flash weapon/ammo/reload/animation/handler state and native aim-queue waiting time every 500 ms. The added Flash callback runs only when requested by the recorder; it does not run each gameplay frame. This will distinguish a stuck game reload from input delivery trouble on the Odin. Capture cleanup cancels the sampler and restores the input wrappers/listeners. The old recorder remains compatible with APKs without these state endpoints.

The first Odin performance capture confirms an active Adreno 740, an 800×419 canvas and Ruffle quality `low`. The page main thread was nearly continuously occupied; 92.78% of CPU self-samples were in WASM, with AVM1 property maps, name lookup, audio decoding/mixing and Rust GC among the hotspots. Browser frame gaps had a 58.35 ms median and a 100.29 ms p95. These are page callback intervals, not measured Flash simulation FPS; CPU percentages do not measure GPU utilization.

The combat audio pass prepares 22 weapon, impact and chainsaw effects as PCM in WebView before streaming the verified v1.31 movie to Ruffle. It retains the movie URL, sound IDs, sample rates, channels and declared durations. Individual clips fall back to MP3 if decoding or validation fails. The performance report includes the prepared clip count. A private pinned-Ruffle fixture played the same 100 overlapping shot and impact sounds in each mode. It produced comparable output energy and about 22% fewer WASM samples with preparation. Odin performance remains a device check.

Sustained gunfire on desktop drove the mixed audio above full scale. The verified game's output now soft-limits loud peaks before Web Audio schedules the stereo buffer, with linked gain for both channels. An audio-only capture with `capture-controller-input.ps1 -Audio` reports mixed peaks and gaps between scheduled buffers without enabling the CPU profiler. The probe restores the original schedule hook and reports audio measurements only.

At an 8,192-frame mixer buffer, a desktop fixture sent 30 evenly spaced sounds through Flash and measured 11 distinct starts. Multiple sounds began at the same buffer boundary. Player and survivor shots, weapon impacts, explosions and the chainsaw release now start individually in the same Web Audio context as Ruffle. The original Flash start is used if direct playback is unavailable. Ruffle still manages the chainsaw loop and its stop calls. The capture's `timedCombatSounds` counts successful direct starts during the sample. Buffer peaks and gaps describe the Ruffle stream before the final shared peak limiter.

The matched 800×420 Odin profile attributes 47% of CPU samples to mouse picking, including 23% to the crosshair's active drag. The verified v1.31 patch ends that drag during crosshair setup and follows the stage pointer on each Flash frame. The pinned-Ruffle fixture checks pointer alignment and confirms the drag ends. The real game also passed desktop aim, fire and daytime transitions. Odin frame pacing still needs a retest.

The next Device-resolution capture has no crosshair drag samples. Ordinary mouse picking accounts for about 37% of sampled CPU time. The combat pointer now uses the frontmost crosshair to route presses and releases to the original firing surface. The bottom-left options area keeps the normal picker, and menu transitions remove the combat handlers. The pinned-Ruffle fixture checks clicks, releases across the options boundary in both directions, and cleanup. The original trail and projectile code stays in use.

The next build replaces only the known SWF's `moveParticle` callback in memory. It preloads the particle receiver, uses Flash's numeric transform accessors, and reuses horizontal velocity after the first update for `bloodParticle`, whose launch angle/energy are fixed by the tested emitter. Other particle types still recalculate their motion. Counts, fade rate, gravity and rotation are retained. The imported file and save data are unchanged. The same SHA-256 guard protects all patches; unrecognized copies are served unchanged.

`node tests/test_particles.cjs` generates an independent Flash fixture using the production Java bytecode emitter and compares it with a dynamic-scope reference in pinned Ruffle. Local tests also paired the new callback with the original private game's bytecode: 100 paired updates matched; repeated 5,000-update batches were approximately 15–20% faster. This is a callback measurement on desktop Chromium, not an Odin or whole-game performance improvement. Heavy shooting/running-zombie performance and audio costs still require the next device check.
